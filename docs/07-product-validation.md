# Phase 7. 사용 이유 검증

실제 대화에서 쓸 말을 얻고, 비슷한 상황에 다시 찾는지 검증한다. 아래는 실험 제안이다. 인터뷰·실사용 결과는 아직 없다.

근거: 2026-10-10 제품 논의와 사용자가 제공한 실패 가설 분석. 분석에 인용된 외부 연구·경쟁 서비스의 성능은 이번 문서에서 검증하지 않았다.

## 범위와 비용

기존 UI와 대화 연습을 활용한다. 첫 대상은 최근 상대의 취향을 몰라 대화가 막힌 경험이 있는 사람이다. 연령이나 성격으로 대상을 단정하지 않는다.

앱 패키징·콘텐츠 대량 추가·결제 개발은 검증 뒤로 둔다. 출시 일정은 늦어지지만, 사용 이유가 불명확한 기능에 쓰는 개발 시간을 줄이려는 선택이다.

상황극은 재미 가설로 따로 둔다. 웃음·공유 반응과 대화에 도움이 된 경험을 각각 기록한다. 두 결과를 하나의 성공 지표로 합치지 않는다.

## 실험 구성

다음 인원·기간은 작은 탐색 실험을 위한 제안값이다. 시장 규모나 통계적 효과를 추정하는 기준은 아니다.

| 단계 | 제안 | 관찰할 근거 | 실패를 의심할 신호 |
| --- | --- | --- | --- |
| 문제 인터뷰 | 최근 2주 내 경험이 있는 5명 | 당시 대화·해결 방법·남은 불편 | 구체적 사례가 없거나 한 번 물어보는 것으로 충분함 |
| 설명 비교 | 같은 소재의 A/B 설명 | 설명 뒤 직접 만든 첫마디·후속질문 | 이름은 기억하지만 다음 말을 못 정함 |
| 대체재 비교 | 평소 도구와 서비스 선택 | 선택 이유·막힌 지점·얻은 말 | 서비스만의 도움을 설명하지 못함 |
| 후속 확인 | 7일 뒤 실제 상황 확인 | 실제 발화·상대 반응·다시 선택한 도구 | 비슷한 상황에서 서비스를 떠올리지 못함 |

후속 기간에 관련 상황이 없었다면 재사용 여부는 판정 보류다. 재방문 요청이나 알림을 보낸 뒤 접속한 것은 자발적 재사용과 따로 기록한다.

## 인터뷰와 비교 과제

진행자는 서비스를 소개하기 전에 최근 경험부터 묻는다.

1. 최근 상대가 좋아하는 것을 몰라 대화가 멈춘 상황을 설명해 주세요.
2. 그때 실제로 무엇을 말하거나 찾아봤나요?
3. 해결 뒤에도 불편했던 점이 있었나요?
4. 비슷한 일이 다시 생겼을 때는 어떻게 했나요?

설명 비교에는 참가자가 모르는 소재를 사용한다. A는 이름·뜻, B는 같은 정보에 상황·주의점·후속질문을 더한다. 길이 차이를 줄이고, 참가자별 제시 순서를 바꾼다. 같은 소재를 다시 읽는 학습 효과는 한계로 기록한다.

예시 과제: 지인이 낯선 캐릭터 굿즈를 보여주며 좋아한다고 말한다. 설명을 읽고 직접 답해 본다. 진행자가 상대 역할로 좋아하는 이유를 말하면, 참가자가 다음 말을 이어간다. 예문 복사는 직접 만든 답변과 구분한다.

대체재 비교에서는 참가자가 평소 쓰는 검색·AI 또는 상대에게 직접 묻기를 선택할 수 있다. 진행자는 특정 도구를 권하지 않는다. 수행 시간과 답변을 기록하되, 한 과제로 도구 전체의 성능을 평가하지 않는다.

## 기록과 판단

진행자는 익명 ID로 기록한다. 대화 상대의 이름·단톡방 캡처는 수집하지 않는다. 녹음이 필요하면 별도 동의를 받는다.

| 기록 항목 | 남길 내용 |
| --- | --- |
| 최근 경험 | 상황, 막힌 이유, 실제 해결 방법 |
| 설명 비교 | 제시 순서, 사전 지식, 직접 만든 답변, 진행자 도움 |
| 재미 반응 | 웃음이 나온 장면, 직접 공유한 내용과 이유 |
| 실제 적용 | 써본 말, 상대 반응, 도움·불편, 자기 보고 여부 |
| 다음 선택 | 비슷한 상황 발생 여부, 선택한 도구, 선택 이유 |
| 반례 | 유용하지 않았던 상황, 상대에게 직접 묻기로 충분했던 경우 |

기획자는 실제 발화 사례와 반례를 함께 검토한다. 역할극 결과는 실제 관계에서의 효과로 해석하지 않는다. 소수 참가자의 결과는 사례 수로 보고하며 전체 이용자 비율로 일반화하지 않는다.

대화 도움과 재선택 사례가 나오면 상황별 안내를 확장한다. 웃음·공유만 나오면 놀이 서비스 가설을 별도로 검증한다. 구체적인 필요가 나오지 않으면 대상과 문제를 다시 정한다.

구매 검증에서는 실제 제공할 범위와 일회 구매·구독 조건을 구분해 제시한다. 현재 [로컬 관심 표시](06-revenue.md)는 구매나 지불 의사 증거로 사용하지 않는다. 제작·검수 시간도 함께 기록한다.

## 실행 상태

- 문서: 검증안 작성.
- 제품: 이번 단계의 코드 변경 없음.
- 사용자 검증: 참가자 모집·실험 미실행.
- 앱: iOS·Android 출시 목표 유지. 기기 테스트·스토어 제출 미실행.
